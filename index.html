Classes, Objects & Instances
● ~15 minutes

You already know the language of OOP. This pre-learning is about using it in the exam. Paper 4 questions give you a scenario and ask you to state, describe or explain an OOP term using that scenario, or to write Python code for it. A textbook definition on its own rarely gets full marks: you need to link it to the classes in the question.

The scenario used throughout this page
A music streaming app called TuneBox stores audio items. Every audio item has a title and a length in seconds, and users can give it a rating from 1 to 5 (it starts at 0, meaning "not rated"). There are two kinds of audio item: songs, which also have an artist, and podcasts, which also have an episode number. Users can build playlists, each with a name, that hold any number of audio items. The app must describe each item and work out the total length of a playlist.

Encapsulation, Getters & Setters
● ~15 minutes
Quick recap: Encapsulation means keeping an object's data and the methods that use it together in one class, and hiding the data by making attributes private. Other code can only reach the data through public methods: a getter returns a value and a setter changes it, usually after checking (validating) it.
Getter

Returns the value of a private attribute. It does not change anything.

def GetRating(self):
    return self.__Rating
Setter

Takes a new value as a parameter, validates it, then changes the private attribute.

SetRating(NewRating) only accepts 1 to 5.
Encapsulation in action
Track = AudioItem("Morning Mix", 245) print(Track.SetRating(4)) # True print(Track.SetRating(9)) # False print(Track.GetRating()) # 4 print(Track.__Rating) # AttributeError
What is happening?
  • 4 is valid, so it is stored and the setter returns True.
  • 9 is rejected, so Rating stays 4.
  • The getter is the only way to read the rating.
  • Reading Track.__Rating directly fails, because the attribute is private.
✎ Worked exam-style question
Explain why the attribute Rating in the AudioItem class is declared as private. [2]
Think of your answer first, then reveal the mark scheme.
Mark scheme — one mark for each point:
  • So it cannot be accessed or changed directly from outside the class / it can only be changed through the class's own methods
  • The setter SetRating() validates the new value, so an invalid rating (not 1 to 5) cannot be stored
Examiner tip: "Explain" needs a reason and a link to the scenario. Naming SetRating() and the 1 to 5 rule is what earns the second mark.
Watch out: a getter must return the value. A "getter" that prints the value cannot be used by other code, and is a common reason for losing marks.

Inheritance
● ~15 minutes
Quick recap: Inheritance lets a subclass (child class) take on all the attributes and methods of a superclass (parent class), and add its own. Use the "is-a" test: a Song is an AudioItem. In Python, the subclass header is class Song(AudioItem): and its constructor calls super().__init__(...) first.
AudioItem
- Title : STRING
- Seconds : INTEGER
- Rating : INTEGER
+ Constructor(Title, Seconds)
+ GetTitle(), GetSeconds()
+ GetRating(), SetRating()
+ Describe() : STRING
△
inherit from AudioItem
Song
- Artist : STRING
+ GetArtist() : STRING
Podcast
- EpisodeNo : INTEGER
+ GetEpisodeNo() : INTEGER
Python — two subclasses
class Song(AudioItem): def __init__(self, Title, Seconds, Artist): super().__init__(Title, Seconds) self.__Artist = Artist def GetArtist(self): return self.__Artist class Podcast(AudioItem): def __init__(self, Title, Seconds, EpisodeNo): super().__init__(Title, Seconds) self.__EpisodeNo = EpisodeNo def GetEpisodeNo(self): return self.__EpisodeNo
What the subclass gets for free: a Song object can call GetTitle(), GetSeconds() and SetRating() even though they are not written in the Song class. They are inherited from AudioItem.
✎ Worked exam-style question
Describe what is meant by inheritance. Use an example from the TuneBox scenario in your answer. [2]
Think of your answer first, then reveal the mark scheme.
Mark scheme — one mark for each point:
  • A subclass takes on / reuses the attributes and methods of a superclass (and can add its own)
  • Example: Song (or Podcast) inherits Title, Seconds and SetRating() from AudioItem / a Song is an AudioItem
Examiner tip: Name both classes in your example and say which way round the relationship goes.
Benefit to quote in the exam: shared code is written once in the superclass, so it does not need to be repeated in every subclass, and a new type (e.g. Audiobook) can be added by writing a small subclass.

Polymorphism & Overriding
● ~15 minutes
Quick recap: Polymorphism means the same method call behaves differently depending on the class of the object it is called on. It happens when a subclass overrides a method: it redefines a method it inherited, using the same name.
Python — Describe() is overridden
class AudioItem: # ... as before ... def Describe(self): return self.__Title class Song(AudioItem): # ... as before ... def Describe(self): # overrides return self.GetTitle() + " by " + self.__Artist class Podcast(AudioItem): # ... as before ... def Describe(self): # overrides return "Episode " + str(self.__EpisodeNo) + ": " + self.GetTitle()
Main program
S = Song("Sunrise", 210, "The Owls") P = Podcast("Space Facts", 1500, 12) print(S.Describe()) print(P.Describe())
Output
Sunrise by The Owls
Episode 12: Space Facts

Same call, Describe(), but different results, because each object uses its own class's version.

Why GetTitle() and not self.__Title? Title is private to AudioItem, so the Song class cannot read self.__Title. It uses the inherited public getter self.GetTitle() instead. This is encapsulation and inheritance working together.
✎ Worked exam-style question
Explain how the Describe() method in TuneBox demonstrates polymorphism. [2]
Think of your answer first, then reveal the mark scheme.
Mark scheme — one mark for each point:
  • Song and Podcast override Describe() / each class has its own method with the same name as the one in AudioItem
  • The same call Describe() gives a different result depending on the object's class, e.g. "title by artist" for a Song and "Episode n: title" for a Podcast
Examiner tip: Two marks need two different points: what is overridden, and how the result changes for each class.

Containment (Aggregation)
● ~15 minutes
Quick recap: Containment (also called aggregation) is a "has-a" relationship: one class stores objects of another class as an attribute, usually in a list. A playlist has audio items; it is not a kind of audio item, so inheritance would be wrong.
Playlist
- Name : STRING
- Items : list
+ AddItem(NewItem)
+ TotalSeconds() : INTEGER
AudioItem
…
The hollow diamond on the Playlist end shows aggregation. Because Song and Podcast inherit from AudioItem, one list can hold a mixture of both.
Python — the Playlist class
class Playlist: def __init__(self, Name): self.__Name = Name self.__Items = [] def AddItem(self, NewItem): self.__Items.append(NewItem) def TotalSeconds(self): Total = 0 for Item in self.__Items: Total = Total + Item.GetSeconds() return Total
Inheritance = "is-a"

A Song is an AudioItem. The subclass gets the superclass's members.

Containment = "has-a"

A Playlist has AudioItems. It stores them and calls their public methods.

✎ Worked exam-style question
Explain why the Playlist class uses containment rather than inheritance. [2]
Think of your answer first, then reveal the mark scheme.
Mark scheme — one mark for each point:
  • A playlist is not a type of audio item / it fails the "is-a" test
  • A playlist has / stores a collection of AudioItem objects (in its Items list), which is a "has-a" relationship
Examiner tip: Use the "is-a" and "has-a" tests with the real class names from the question.
Watch out: in TotalSeconds(), return Total must be after the loop. Inside the loop it would stop after adding only the first item.

✓ Summary — CIE 9618 Topic 20.1: Object-Oriented Techniques
Class, object, instance: a class is the blueprint; an object is one instance of it, created by calling the constructor. Attributes store data; methods act on it.
Encapsulation: data and methods are bundled in one class, and attributes are private (self.__Name), so they can only be reached through public methods.
Getters & setters: a getter returns a private value; a setter validates a new value, then stores it. Not every attribute needs a setter.
Inheritance: a subclass ("is-a") gets the superclass's attributes and methods, adds its own, and calls super().__init__() in its constructor.
Polymorphism: a subclass overrides an inherited method with the same name, so the same call gives different results for each class.
Containment (aggregation): a class ("has-a") stores other objects in a private list and uses their public methods. In the exam, always link every term to the scenario.
